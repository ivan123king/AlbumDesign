# 项目目的与技术选型

## 项目目的

开发一款运行于 Windows 11 的简易画册制作软件。用户管理素材，手工摆放图片与中文文字，制作多页 A4 画册，最终导出 PDF 交给商家打印。

优先保证排版直观、工程独立可搬迁、保存可靠以及数百页操作可用。功能范围以 [业务规划](../业务/业务规划.md) 为准。

## 技术选型

| 项目 | 选择 | 原因 |
| --- | --- | --- |
| 桌面运行环境 | Electron | 提供桌面窗口、本地文件能力与 Chromium 排版 |
| 语言 | TypeScript，启用严格类型检查 | 明确工程数据和进程通信接口 |
| 界面 | React + HTML/CSS | 实现素材树、页面对象树、菜单及属性面板 |
| 编辑画布 | HTML 元素绝对定位、CSS transform 与 z-index | 实现图片与文字的移动、等比例缩放、叠层和视图缩放 |
| 文字排版 | CSS writing-mode、字体和间距属性 | 实现横排、竖排及多行多列文字 |
| PDF 输出 | 独立导出窗口、打印样式、webContents.printToPDF | 复用页面排版，生成指定物理尺寸的 PDF |
| 工程数据 | JSON、TypeScript 数据类型和运行时校验 | 逐页保存，识别损坏或不兼容的数据 |
| 文件操作 | 主进程中的 Node.js 异步文件接口 | 处理中文路径、复制、删除与保存失败 |
| 构建与打包 | Vite、Electron 打包工具 | 分别构建前端和桌面程序，输出 Windows x64 成品 |

在搭建阶段检查已有 Node.js/npm，固定 Electron、React、TypeScript、Vite 和打包工具版本并提交依赖锁文件。优先使用预编译版本，不安装无关工具链。依赖与缓存尽量使用项目或指定工具目录。

软件运行不依赖网络服务。初期不增加数据库、复杂状态管理或图形引擎；PDF 合并库仅在分批导出确有需要时引入。

## 最小模块划分

| 模块 | 职责 |
| --- | --- |
| 主进程 | 窗口、工程读写、页面与图片文件操作、导出任务 |
| preload 桥接 | 暴露必要业务接口，校验通信数据，隔离界面与本地能力 |
| React 界面 | 菜单、三栏布局、页面对象树、属性操作与当前页编辑 |
| 共享数据模型 | 页面尺寸、图片对象、文字对象、叠层和通信类型 |
| 页面渲染与导出 | 共用 HTML/CSS 页面组件，区分编辑控件与打印样式 |

模块是职责边界，初期按需要组织源码，不强制拆成独立库。

## 当前画册存储与素材实现

- `src/shared/album.ts` 定义画册格式及受限通信类型。`project.json` 格式版本为 `1`，字段为 `formatVersion`、`name`、`defaultOrientation`、`pages`、`nextPageNumber`。页面引用使用 `id`、`name`、`directoryName`；新画册 `pages` 为空，下一页面编号为 `1`，旧版无页面画册可直接继续使用。
- `src/main/album-store.ts` 负责清单校验、真实素材目录扫描、分组和复制。素材树直接读取 `assets`，不另存素材清单；素材操作即时落盘，无需点击页面“保存”。
- `src/main/album-ipc.ts` 统一处理菜单和界面操作，原生对话框提供外部文件路径。主进程固定当前画册会话，素材请求仅接受会话 ID 与相对于 `assets` 的路径；操作互斥，状态带递增版本号。
- 新建画册要求空目录，清单先写同目录临时文件；图片先复制到目标目录临时文件，核对格式并解码后，以排他方式发布正式文件。同名递增附加 ` (1)` 等后缀，不覆盖已有文件。支持硬链接的磁盘优先使用同卷链接发布，其余情况采用排他创建和异步复制；后者不承诺断电时原子提交。
- `src/main/image-validator.ts` 用独立沙箱窗口逐张解码，完成后释放资源，批次结束销毁窗口。受限 `album-import` 协议只接受本批临时文件的随机令牌，不接受磁盘路径；令牌在单项完成后撤销。
- 目录扫描忽略符号链接和目录联接并提示；写入逐层检查路径，不跟随目录链接。只通过文件头和解码识别支持的 JPEG/PNG，不将修改后缀作为格式转换。
- `AssetsPanel` 提供目录与预览 TAB，`AssetGallery` 用滚动容器的 IntersectionObserver 控制附近卡片的图片挂载，远处卡片只保留名称占位；离屏卸载会取消未开始的请求。目录 TAB 不请求缩略图。`AssetPreview` 使用原生 dialog，一次加载一张原图。
- `src/main/asset-images.ts` 提供独立于画册写入队列的浏览租约与单任务生成队列；preload 只接收当前会话、素材相对路径、用途与请求 UUID。`album-asset` 地址只含租约令牌，每次读取重新核验会话和源文件，释放或换画册后失效；不广播业务 busy，也不暴露任意路径。
- 缩略图通过 `ImageValidationTask` 在后台以 ImageBitmap 解码并绘制成最长边 256 像素的 PNG，保留照片方向与透明度；绘制后显式关闭原图位图。小图编码只在后台与主进程间传递，React 只保存地址；后台窗口每生成 16 张或空闲两秒后销毁。后台跨源读取仅允许持随机任务令牌的 `album-import` 资源。
- 素材缓存目录固定为 `cache/thumbnails/assets`，逐层拒绝链接，旧画册缺失目录时按需创建。缓存名由版本、相对路径、文件大小及修改/变更时间摘要确定，排他写入；重试可重建对应缓存。完整缓存可删除重建，暂不自动清理历史失效缓存。

## 当前页面存储与编辑实现

- `src/shared/canvas.ts` 定义图片和文字的联合对象模型。新页面使用 `canvas.json` 版本 `2`，尺寸固定为 `210 × 297 mm`，编辑视角、页内图片计数、对象 ID 与叠层分别保存；版本 `1` 纯图片页面兼容读取，载入不改写磁盘，增加文字或自由角度并保存时升级。工程清单仍为版本 `1`，旧程序会拒绝新版本页面而不覆盖。
- 对象共用位置、长宽、自身角度与叠层；图片独有文件名及源名称。文字独有内容、横竖排类型、字体、基础字号、颜色、字间距、行列间距、横排分栏及栏间距，以及固定的 `layoutWidthMm/layoutHeightMm` 排版区域。可选 `contentBounds` 记录相对此区域的毫米内容边界；新文字实际尺寸与内容边界保持同一缩放比例，缺少此字段的旧文字沿用整个区域。文字不占图片编号。
- 对象共用可选 `displayName`，保存在本页 `canvas.json`。缺省沿用来源名或正文摘要，载入旧页面不补写字段、不升级格式；恢复默认删除字段。`objectLabel` 统一管理界面名称，`renamePageObject` 接收会话、页面、对象 ID 和字符串或 null，主进程及读盘共用名称校验，正文编辑保留已有名称。操作仅更新当前页草稿，不改文件路径、对象 ID 或叠层。
- `src/main/page-store.ts` 只缓存当前页。创建页或加入图片前先持久化预留编号；失败可以留下空号，但不覆盖或复用已有文件。拖入先复制并后台解码，再发布独立页面文件，成功后提交对象，失败清理本次副本。
- `src/main/json-storage.ts` 使用同目录临时文件、异步写入和替换；替换前核对正式文件类型及载入时原文，发现外部修改则拒绝覆盖。主进程业务操作互斥，避免内部并发写入。
- 页面创建、页面名称、页序和删除，以及图片加入和对象删除即时保存；对象名称、文字创建/编辑、对象位置/尺寸/角度/叠层和页面方向修改保留在主进程当前页草稿，使用工具栏“保存”或 Ctrl+S 提交。离页、切换画册、关闭和结构操作前统一确认保存、放弃或取消；文件失败保留可重试草稿。
- 图层以 `zIndex` 为唯一依据，列表按降序显示，画布按该值叠放。受限 `reorderPageObject` 接口接收当前会话、页面、对象 ID 及从顶层起的零基目标位置，主进程校验后将叠层整理为连续整数；无效参数不部分修改，同位置不产生草稿。对象数组存储顺序、文件编号与格式版本不因重排改变。列表拖动仅在本地显示插入线，松手提交一次，共用右键菜单的排序接口。
- 删除先将页面目录或图片改为同目录临时名称，JSON 提交失败则放回；提交后真实删除，页面删除同时清理该页缓存。递归删除前拒绝链接。此流程处理正常异常，不承诺断电后的跨文件事务恢复。
- `album-page` 资源协议仅接受当前会话、页面和对象 ID，由主进程解析到该页普通图片文件，拒绝任意路径及失效会话。切页卸载旧图片元素，不把原图二进制放入 React 状态；尚未实测大图峰值内存。
- `CanvasEditor` 使用 HTML 图片与毫米绝对定位。横版整页执行 `translateY(210mm) rotate(-90deg)`；屏幕位移先除查看比例，再做逆旋转，得到基础毫米位移。拖动帧只更新当前图片 DOM，松手才提交草稿。
- `ObjectSelection` 共用跟随角度的独立选框，不提高对象叠层。对象中心先转到编辑视角，选框以中心定位并叠加自身角度；控制点和旋转图标除以查看比例，保持固定屏幕大小。纸张仍用 `overflow: clip`，焦点使用 `preventScroll`，保留越界选择稳定性修复。
- 缩放依次撤销查看比例、整页旋转和对象自身旋转，在对象局部坐标计算固定对角或对边，再还原基础几何数据。图片八点，文字仅四角；主进程拒绝文字的非等比尺寸。旋转使用鼠标相对对象中心的 `atan2` 差值并跨 0°连续累计，保存时归一化到 `[0,360)`；旋转不改写长宽和中心。
- `TextContent` 用真实 HTML/CSS 和 `writing-mode` 排版。弹窗确认时等字体就绪，通过同一预览 DOM 的 Range 测量内容，撤销预览比例后附加半毫米边距；主进程校验并保存边界及选框尺寸。绘制时平移内层至内容起点，再按 `--text-scale` 整体缩放；固定排版区不因选框收紧重新换行。再次编辑以实际字号和原排版区重建布局。字体由有限主进程接口异步检测首批 Windows 字体，缺失明确提示。
- 尺寸表单统一按对象自身长宽显示，与角度分开；图片默认等比但允许取消，文字始终等比。确认时中心固定，主进程一次验证更新。图片用 `object-fit: fill` 呈现单轴拉伸，原图不改写。

## 关键技术约定

- 正式页面模型以竖向 A4 为基础坐标，页面尺寸、对象位置和对象宽高按毫米保存；字号按磅保存。阶段 1 的固定样例不作为持久化数据模型。
- HTML/CSS 通过绝对定位摆放对象。横版编辑视图整体逆时针旋转 90°；切回竖版恢复基础视角。指针坐标需经过视图旋转、查看缩放的逆变换，再写入页面坐标。
- 查看缩放与整页视角均作用于页面外层，不累计改写对象数据。仅切换横竖视角，最终 PDF 内容布局应一致。
- 对象自身旋转角度单独保存为任意有限角度。新对象按当前编辑视角摆正：竖版初始为 0°，横版初始为 90°；初始化后切换视角不改写对象角度或坐标。
- 页面使用稳定编号；`project.json` 的页面数组顺序决定页码。图片编号在每页内递增，叠层独立保存。
- 每个图片对象拥有独立图片文件，复制对象也分配新图片文件，避免删除时影响其他对象。
- 图片导入复制原文件并保留后缀，不把改后缀当作格式转换；显示时处理照片方向信息。
- 画布使用页面模型；编辑和 PDF 共用页面组件及排版规则。导出隐藏选框和控制点，不截图或将整页栅格化生成 PDF。
- 横排使用 `horizontal-tb`，竖排使用 `vertical-rl`，明确字符朝向；分列和换行用实际中文、标点及英文数字样例验证。初期使用文字输入弹窗编辑内容。
- 文本框等比例缩放，字号、字间距和行列间距同步变化；只应用一次缩放，避免 CSS 变换与字号调整叠加。缩放本身保留原有行列排布。
- 只挂载当前页对象；编辑预览按显示需求加载图片，保留原图供导出。切页释放不用的资源，避免一次加载数百页原图。
- 页面树先显示文字，按需展开对象；素材预览与页面缩略图使用小图。大列表仅在实测需要时加入虚拟滚动。
- 拖动通过帧调度更新当前对象，结束后提交数据；不在每次指针移动时保存文件或刷新全部 React 状态。
- 文件复制和读写使用异步接口；耗时图片处理放到工作线程或后台任务，不用同步操作阻塞界面。
- JSON 保存采用同目录临时文件和替换流程，验证 Windows 上替换失败的处理。跨文件操作需要处理失败和恢复，避免引用不存在的图片。
- `contextIsolation` 开启，渲染进程关闭 Node.js 集成；通过有限 preload 接口操作工程。校验路径在当前工程范围内，素材使用受限本地资源协议加载，不暴露任意磁盘读写。
- 第一版不承诺 PDF/X 或专业色彩管理。以商家接受的 PDF 规格试印验证，检查字体嵌入、物理尺寸和有效图片清晰度。
- 对外发布前核对依赖和字体的分发许可；成品携带 Electron 运行环境，用户不需要安装 Node.js 或前端开发工具。

## PDF 导出约定

- 使用独立导出窗口，`@page` 和打印参数统一设置竖向 A4（210 × 297 mm），关闭默认页眉页脚与默认页边距，保留背景。
- 打印使用竖向基础坐标与对象自身旋转角度。若复用横版视图组件，打印外层整体顺时针旋转 90°还原至竖向纸张范围，避免对对象重复应用旋转或缩放。
- 不通过 PDF 页面旋转标记改变阅读器中的纸张朝向；两种编辑方向导出后，PDF 页面均宽小于高。
- 导出使用原图，等待图片解码和字体加载完成，再调用 `printToPDF`。
- 每页设置明确分页和页面边界裁切，验证混合横竖页面，避免浏览器自动缩放或插入空白页。
- 数百页不一次挂载全部原图。先验证单页和小批量导出，再按实测确定批次与合并方案；合并时也检查峰值内存。
- 字体嵌入、竖排、透明叠层和物理尺寸以导出样例及试印结果验收，不因浏览器能显示就认为打印一定正确。

## 开发原则

按 [实现计划](实现计划.md) 推进。先完成保存重开和单页排版闭环，尽早验证文字打印与数百页资源释放，再完成导出和交付。不提前实现插件、复杂富文本、自动布局或自研图形引擎。
